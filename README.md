# Şirin Dad — сайт для заказа тортов и выпечки

Полный стек: Node.js + Express + SQLite (backend), чистый HTML/CSS/JS (frontend), фото — через Cloudinary, уведомления о заказах — через Telegram-бота.

## Что внутри

- Публичный сайт: каталог по категориям, корзина, оформление заказа (имя/телефон/адрес), 3 языка (AZ/RU/EN), валюта AZN
- Оплата: карта-на-карту (Birbank) — клиент видит номер карты в оформлении заказа, переводит сам, указывает с какой карты и когда. Никакие данные карт через сайт не проходят — это безопасно и не требует лицензии платёжного оператора
- Админ-панель (`/admin`): заказы со сменой статуса, товары (добавление/удаление, до 6 фото, 3 языка, категории), категории, настройки сайта (телефон, адрес, описание, номер карты), смена пароля
- Уведомление о новом заказе в Telegram-бот
- Защита: bcrypt-хеш пароля, JWT в httpOnly cookie, rate-limit на логин и заказы, валидация всех входных данных, helmet-заголовки, лимиты на загрузку файлов (5MB, только jpg/png/webp)

## Запуск локально

```bash
cd sirin-dad
npm install
cp .env.example .env
```

Открой `.env` и заполни:
- `JWT_SECRET` — любая длинная случайная строка
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` — логин/пароль первого админа (создаётся автоматически при первом запуске)
- `CLOUDINARY_*` — зарегистрируйся на cloudinary.com (бесплатно), возьми Cloud name / API Key / API Secret из Dashboard
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — создай бота через @BotFather, узнай свой chat_id через @userinfobot

```bash
npm start
```

Сайт: http://localhost:3000
Админка: http://localhost:3000/admin

## Деплой на GitHub + Render

1. Создай репозиторий на GitHub, залей туда всю папку `sirin-dad` (файл `.env` НЕ заливается — он в `.gitignore`, это правильно, там секреты)
2. На Render: New → Blueprint → подключи репозиторий (в проекте уже лежит `render.yaml`, Render сам всё настроит)
3. В Render Dashboard → Environment добавь те же переменные, что в `.env` (кроме PORT — Render сам его выставляет)
4. Важно про план: SQLite-база и загруженные файлы требуют **постоянного диска** — на бесплатном тарифе Render его нет, файлы будут стираться при каждом передеплое. Я поставил в `render.yaml` план `starter` (~7$/мес) с диском на 1GB — для реального бизнеса, где нельзя терять заказы, это must-have, а не опция. Это не будет проблемой для фото — они всё равно на Cloudinary, но сама база заказов должна жить на диске.

## Чтобы сервер не засыпал (Render free/starter спит после 15 мин без запросов)

Зарегистрируйся на **cron-job.org** (бесплатно) или **UptimeRobot**, создай задачу, которая раз в 10-14 минут делает GET-запрос на:

```
https://твой-сайт.onrender.com/health
```

Это будет держать сервер "живым". Только твой домен из Render впиши.

## Известные ограничения / что стоит добавить позже

- Сейчас один админ-аккаунт (тот, что задан в `.env`). Второй аккаунт для товарища можно добавить прямым SQL-запросом в базу или отдельным маленьким скриптом — скажи, если нужно, сделаю.
- Автоперевод названий товаров не встроен (по твоему выбору — вводишь на 3 языках вручную).
- Нет email/SMS клиенту о статусе заказа — только вы видите его в админке и в Telegram. Если понадобится уведомлять клиента (например, SMS "заказ готовится") — это отдельная (платная) интеграция типа Twilio, скажи если интересно.
